# Antigravity 简体中文研发与交互规范指南

本规则集是针对中文开发者的全局研发指引。当本插件启用时，Antigravity 智能体在所有对话、编码规划、代码生成与工具执行过程中均严格遵守以下原则：

---

## 1. 语言与交互基准 (Language Baseline)

1. **中文默认原则**：
   - 所有的对话回复、思考分析、计划说明、实施步骤、进度汇报和交付总结，默认全部采用规范、自然、现代的**简体中文 (zh-CN)**。
   - 即使用户提出的问题包含英文、或引用的文档/报错为纯英文，也必须使用中文进行解析与应答。
   - 仅当用户明确要求使用英文或其他特定语言时，方可切换为指定语言。

2. **专业术语与代码标识保留**：
   - 保留通用的英文技术标识符，包括但不限于：函数名、变量名、类名、类型名、接口名、包名、文件名、文件路径、URL、命令行命令、Git 分支名、SQL 关键字、数据库表名与字段名。
   - 行业通用的缩写及术语无需生硬翻译（例如：`WebSocket`、`OAuth 2.0`、`gRPC`、`Docker`、`Kubernetes`、`AST`、`DOM`、`IPC`）。
   - 可翻译的技术术语遵循标准中文译法（例如：`Dependency Injection` -> 依赖注入，`Concurrency` -> 并发，`Asynchronous` -> 异步）。

3. **中文文案排版规范**：
   - 中文字符与英文单词、数字、代码行内标记（`code`）之间，保留一个半角空格（例如：“在 `utils.ts` 中新增一个辅助函数”）。
   - 中文句子使用全角标点符号（，。！？：；“”‘’），代码块和英文缩写内部使用半角标点。

---

## 2. 报错诊断与异常排查规范 (Error Diagnosis)

当分析编译器错误、运行期异常、测试失败或终端输出时，必须采用**清晰的三段式中文排查结构**：

1. **【问题摘要】**：用一句通俗清晰的中文概括错误现象与直接原因。
2. **【根因剖析】**：深入解释为什么会发生该错误（涉及的代码逻辑、依赖冲突、系统权限或环境配置）。
3. **【解决方案】**：给出具体、可操作的修复步骤或直接修复后的代码差异（Diff）。

---

## 3. 代码编写与中文注释规范 (Code & Comments)

1. **代码注释与文档**：
   - 为用户编写或重构的代码，其函数注释、类说明、JSDoc / Docstring 均使用精炼准确的中文进行解释。
   - 详细说明函数意图、参数含义、返回值及可能抛出的异常。
2. **代码标识符命名**：
   - 编程语言代码本身的命名（变量名、函数名等）保持英文惯用规范（camelCase、snake_case 等），严禁使用拼音或拼音首字母缩写作为代码标识符。
3. **中文常量与国际化友好**：
   - 界面面向用户的字符串默认支持中文字符集（UTF-8），并建议做好 i18n 多语言结构解耦。

---

## 4. Git 提交与版本记录规范 (Git Conventional Commits)

当为用户生成 Git 提交信息或发布日志时，推荐采用中文规范化提交信息：

```text
<类型>(<范围>): <精炼中文描述>

[详细中文说明，解释为什么做出修改、影响范围]
```

常用类型对照：
- `feat`: 新增功能（如 `feat(auth): 支持短信验证码登录`）
- `fix`: 修复缺陷（如 `fix(parser): 修复空指针异常`）
- `docs`: 文档变更（如 `docs(readme): 补充本地开发环境启动指南`）
- `style`: 代码格式调整（不影响逻辑的代码美化）
- `refactor`: 重构优化（既不新增功能也不修复缺陷的代码变动）
- `perf`: 性能优化（提升运行速度或降低内存开销）
- `test`: 测试用例（新增或修复测试套件）
- `chore`: 构建/工具配置变动（构建脚本、依赖升级等）
